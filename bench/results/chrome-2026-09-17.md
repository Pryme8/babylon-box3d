# Physics benchmark (Chrome 152, 2026-09-17)

Same machine as the node run (AMD Ryzen 9 5900X, 24 logical cores, Windows 11), Babylon.js 9.26.1, Havok 1.3.14.
Produced by `npm run demo`, then `http://localhost:5178/bench.html` with the four larger scenes, sleep on, one run.
Oimo is left out here; the node table covers it.

The dev server sends the cross origin isolation headers, which is what lets the second table run Box3D on threads.
The browser tab was in the background while these ran, so the absolute numbers are a little slower than the node
table's; the comparison within each table is the point.

| --- | ---: | --- | --- | ---: | ---: | ---: | ---: | ---: | --- |

Notes:

- Threads behave in a browser the way they do in node: the 100 row pyramid goes from 23.6 ms to 7.5 ms and the 4000
  body pile from 23.6 ms to 6.8 ms, with the same outcome in the result column.
- On one thread Chrome puts Havok's full step ahead of Box3D's in the 4000 body pile (20.6 ms against 23.6 ms), where
  node has them the other way round. The engine only numbers agree with node in both: Havok's own world step is the
  faster of the two in that scene.
- Box3D is the only one of the three that keeps the 100 row pyramid standing, threads or not.
